# Public list publication timestamp implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Return and render the actual publication time for public list details, matching Figma without confusing list creation time with publication time.

**Architecture:** Add `rewind.lists.published_at` and a database trigger that sets it on public visibility transitions. Backfill currently public lists from `created_at`. Extend only the public-list detail API contract and render the localized relative time in the owner line.

**Tech Stack:** PostgreSQL/Supabase migration, Supabase Edge Function, React, TypeScript, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-28-list-publication-timestamp.md`

## Global Constraints

- Do not publish `published_at` for private lists.
- The database trigger owns publication transitions; clients cannot set the timestamp.
- Preserve existing list-detail layout and dynamic owner/movie content.
- No hosted Supabase, production data, Figma file, or deployment changes during local implementation.

## Review Focus

- New list created public gets a non-null timestamp from the database.
- Private-to-public transition sets the timestamp; public-to-private clears it; republish sets a newer timestamp.
- A public detail response includes ISO `publishedAt`; private list remains unavailable publicly.
- UK/EN relative wording and `<time datetime>` render correctly with reduced-motion/locale-independent layout.
- Existing public-list geometry and access controls remain unchanged.
