# REWIND — план робіт

## Ціль і межі

Завершити повний UK/EN REWIND на безплатному стеку GitHub Pages + Supabase PostgreSQL/Edge. Зберегти чинні маршрути й API-контракти, числові ID, ролі, приватність, доступність та власність REWIND над профілями. Spring Boot/MySQL/Redis/Mailpit лишаються локальними; їхні дані й volumes не перемикати та не видаляти.

Локальна копія `master` відстає від `origin/master` і містить багато незакомічених змін. Не скидати, не очищати й не зливати все upstream одним пакетом; спершу провести file-by-file semantic review і переносити лише підтверджені зміни вузькими блоками.

## Безпекові й міграційні правила

- Не відкривати `rewind` через Supabase Data API; не змінювати Supabase `auth` schema. RLS/grants лишаються вузькими.
- Не зіставляти акаунти за email; не змінювати роль з user metadata.
- Не переносити чи видаляти локальні MySQL дані без перевіреного зашифрованого backup, row/ID/FK reconciliation і rollback.
- Не класти SMTP, Supabase secret/service keys, DB passwords або одноразові Auth links у Git, frontend, логи чи чат.
- Не комітити, не пушити й не розгортати нові зміни без окремого прямого прохання. Історичні докази — у [release archive](RELEASE_EVIDENCE_2026.md); актуальний короткий стан — у [PROGRESS.md](../project/PROGRESS.md).
