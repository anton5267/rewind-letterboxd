# REWIND — поточний прогрес

Оновлено 21.11.2026. Робочий порядок — у [PLAN](../../PLAN.md), вимоги — у [PROJECT_REQUIREMENTS](PROJECT_REQUIREMENTS.md), перевірки — у [RELEASE_EVIDENCE](../operations/RELEASE_EVIDENCE.md).

## Опубліковано

- **Сайт і API.** GitHub Pages обслуговує UK/EN React frontend. Hosted `rewind-api` v66 ACTIVE; попередній read-back збігався з локальним runtime 80/80, але свіжі read-backs підтвердили, що hosted `writing_credit.ts` ще не виключає storyboarding/script supervision/script coordination, а hosted `writer_filmography.ts` ще формує careerJobs лише з genre-filtered writing-credit вибірки; локальні виправлення не закомічені в `master`. Read-only aggregate із 4,774 live credits показав 189 збігів старого фільтра та 149 після виправлення; у published catalog 38 людей не мають інших Writing-кредитів і можуть помилково відображатися у Writer API та writer credits у Movie Details. Production Pages ще на попередньому bundle: read-only acceptance знайшла стару actor UI та відсутній writer route. [CI](https://github.com/anton5267/rewind-letterboxd/actions/workflows/ci.yml), [Pages](https://github.com/anton5267/rewind-letterboxd/actions/workflows/deploy-pages.yml).
- **Акаунти.** Hosted signup confirmation, recovery/reset і sign-in пройшли на disposable identities. Профілі пов’язані з Auth UUID. Опубліковані email-change UI/callback, owner-only names, location/pronoun, загальні й індивідуальні reply preferences. Початкове оновлення токена очікує профілю перед перевіркою Admin. Home та Header очищають стан при зміні ID користувача. Окремі cross-tab/late-response fixtures пройшли 6/6 для Home і 6/6 для unread counters Header.
- **Функції.** Каталог, ratings/reviews, private/public lists, list comments, follow/block, activity, messages/notifications, Journal і supported Admin controls доступні в hosted-стеку. Додані profile avatar/banner, pin і ranked/unranked lists, Journal media та Community public details.
- **Останні UI зміни.** Шапка статті Journal та її стилі відокремлені. Відновлені тло, breadcrumb, округлення колажу й reader columns; legacy/media/audio/language/error перевірки пройшли. Shared Header/Footer використовують оригінальні Figma SVG; desktop search border, nav slots/opacity й UK/EN keyboard/geometry перевірені у 10 комбінаціях. Desktop Header має окремий фон і контрастний scroll-стан, 5 цільових сценаріїв пройшли. Messages/notifications оновлюються у видимій вкладці з guards від запізнілих відповідей. Person має десятиліття, окремі ACTOR/DIRECTOR/PRODUCER фільмографії та UK/EN біографії з позначеним English fallback і More/Less.
- **Person jobs — локальний блок.** Edge v66 read-back додав crew-credit ingest і writer filmographies; `movie_crew_credits` має RLS і 4,774 рядки. Живі API producer Adam Sidman, actor/producer Amanda Seyfried і writer Rebecca Sonnenshine підтверджують detailed jobs; локальний summary відповідає Figma `Actor | Producer | Executive`. Після нового зіставлення phone frame прибрав дубльований агрегований рядок з hero: повні jobs і локалізовані rating values доступні у назвах посилань на film cards; візуально картки лишаються poster-only як у Figma. Deno check/tests тепер **170/170**; mapper відхиляє некоректні person IDs та порожні імена crew records і зберігає snapshot понад 500 credits. Frontend build — 407 modules, усі шість Person Playwright suites — 15/15. Phone hero запитує backdrop через публічний Movie Details endpoint v66. Live UI acceptance для актора й сценаристки пройшла: hosted actor/writer/movie GET-и відповіли 200, картинки видимі й завантажені на 393×852, overflow немає. 21.11 локальний Vite UI пройшов білінгвальне Chrome acceptance на реальних hosted API-відповідях для чотирьох варіантів (director Chloé Zhao з чотирма jobs, producer Alex Garland із producer/writer, actor Ahn Hyo-seop без crew jobs, writer Freida McFadden із Book): локалізовані role summaries, детальні кредити й ratings доступні в accessible names посилань на film cards в UK/EN на 320/393/768/1440px без overflow і browser errors. Це не покриває всі 451 job або Figma parity. Перша невдала перевірка була через неправильний CSS Module selector; виправлений assertion пройшов. Точний Brad Pitt asset/content і повна frame parity залишаються відкритими.
- **Settings layout.** Desktop identity/media layout і mobile toolbar мають цільове UK/EN покриття. Email/Pronoun та Location/Replies вирівняні, username/display name стоять поруч. Два field-order сценарії підтвердили drafts, resize і Save/reload. Live геометрія та Tab перевірені. Email вирівняний до 79px, Pronoun/Replies мають 300px і сусідні підказки. Довгі назви та приклад вживання займенника пройшли два UK/EN сценарії й production EN звірку. Phone previews використовують 20px corners, екран завершується діями акаунта, зайвий nav spacer прибраний. Footer і відступ відновлюються на звичайному профілі. Favorites order зберігся після live keyboard move та reload; два QA entries очищені. Телефонні заголовок PROFILE, drag і короткий текст підказки відповідають Figma; цільовий phone E2E перевірив текст, клавіатурний опис, drag, reload, focus і tap на деталі. Повна frame parity відкрита.
- **Тестові джерела.** Переглянуті 16 відмінних/local-only файлів, узгоджені lists/Admin та root/project-prefix Auth fixtures. 17 цільових перевірок пройшли. Локальні тести publication editor збережені з відповідним варіантом реалізації.
- **Мобільна навігація.** П’ять оригінальних Figma іконок винесені в MobileNavIcon та його CSS. Rail/targets, завантаження assets, UK/EN guest/member і keyboard navigation перевірені на 320/393px. Типографіка й повна shared-frame parity відкриті.
- **Структура.** README англійською з трьома схемами. Окремий RouteDocumentTitle синхронізує назву вкладки з поточною сторінкою. Admin використовує локалізовану назву розділу. Переходи, history/query та запізніла відповідь фільму мають шість UK/EN fixture перевірок. Edge розділений на contracts, HTTP, repositories і runtime. Власний/публічний React-профілі розділені на hooks, views і тематичні стилі. Докладна історія документації винесена в [архів](../archive/README.md).
- **Локальна сумісність.** PostgreSQL baseline та MySQL→PostgreSQL rehearsal раніше пройшли на ізольованих копіях зі збереженням IDs/FK/NULL/sequences. Локальні й hosted записи мають відмінності, подальше перенесення очікує звірки.

- **Звірка джерел.** Admin movie editor використовує захищені деталі для прихованих фільмів. Live save/reload та UK/EN відкриття прийняті, QA очищено, початкові 50 фільмів звірені за повним hash. SQL reader винесений у тематичний модуль. Поточні hosted migration versions/names збігаються з 56/56 локальними файлами; відсутній у Git `20261116144505_movie_crew_credits` реконструйовано за read-only metadata, isolated replay пройшов на PGlite PostgreSQL 17.4, а повний baseline replay на hosted PostgreSQL 17.11 ще відкритий. Favorites і Admin queries мають actor/request guards. Поле жанрів має окрему UK/EN назву й точну помилку завантаження; цільові recovery сценарії пройшли. Review editor має окремі стилі й цільове fixture-покриття. Live EN desktop/UK phone edit, Cancel/Save focus, hide/show та public 404/200 прийняті. QA фільм і залежні записи очищені, початкові 50 фільмів звірені за full-row hash. Admin movie edit зберігає пропущену originalLanguage, nullable castOrder та порядок доданих акторів. Цільові cast-order fixtures пройшли 6/6 окремо в release й original checkout, обидва typecheck успішні. Supabase config явно задає public schemas, grants rewind для anon/authenticated лишаються забороненими.

- **Live списки.** Owner create/order/rank/reply, очищення опису, pin/save/reload та comment create/edit/reload/delete підтверджені через production UI і SQL. Приватизація автоматично зняла pin, анонімний GET повернув 404. Тестовий список/коментар очищені, початкові system lists і редаговані поля профілю звірені. Виправлені private-card links, UK/EN navigation 2/2 та попередній Retry/focus 1/1 пройшли. Admin feature/unfeature/hide/publish, populated feed і перестановка двох добірок прийняті live через Admin/SQL/guest API. Reload і boundary focus підтверджені, QA очищено. Після завершення старого cache window наступна перестановка одразу відобразилася після звичайного reload. Edge v61 прибирає кешування стрічок і деталей списків після відтвореної застарілої картки.

- **Live профіль.** UK save/reload та EN clear/reload підтвердили display name, owner names, bio, location, pronoun і три reply preferences. Публічна відповідь приховує names/email. Website link пройшов save/reload/public-read/clear, початковий стан відновлений. Media upload зупинений до передачі файла через відсутній дозвіл file URLs у Chrome extension.

- **Live Journal.** Create/edit, rich/plain text, media clear, publish/unpublish і UK/EN reader прийняті. Тестова стаття очищена, аудит збережений. Фокус структурних дій редактора перевірений двома UK/EN fixtures і після публікації у Chrome.

- **Films discovery.** Додано реальну секцію Crew Picks на `/films/discover` через існуючий `/lists/public/team` feed. Секція має UK/EN текст і loading/error/empty/retry стани; typecheck і production build проходять.
- **Живий hosted review 21.11.2026.** Deploy commit `ae7c2d8` пройшов GitHub Pages workflow. Live admin session підтвердила Profile, Settings, Notifications і Admin Movies без тестових мутацій. `/lists/public/team` повернув `{ "content": [], "totalElements": 0 }`, тому Crew Picks залишає справжній empty state і не додає вигадані sample cards.

## Залишилося

| Блок | Конкретна умова завершення |
| --- | --- |
| Recovery | Encrypted production export і disposable PostgreSQL 17 restore успішні (Actions runs `43932021794`, `44040026836`); row-level source reconciliation не виконана. Auth, Storage, settings і secrets потребують окремого recovery handling. |
| Локальний source/data | Hosted Edge v66 read-back відповідав локальному runtime на попередньому checkpoint (80/80); свіжі read-backs підтвердили різниці у `writing_credit.ts` і `writer_filmography.ts`. Read-only aggregate: 4,774 credits, 189 збігів старого фільтра і 149 після вилучення 40 storyboarding/script supervision/coordinator записів. Кандидат закомічений як `319cd04`, запушений у `codex/release-reconcile` від `origin/master` `74f8018`, GitHub CI run `45174443013` успішний; у master не злитий і не розгорнутий. Docker daemon перевірено: контейнерів немає, Compose `.env` і `rewind-db` volume відсутні. ZIP має порожню `DatabaseSnapshots`; read-only пошук backup-імен у Downloads/Documents результату не дав. Користувач повідомляє, що local MySQL втрачена; потрібне підтверджене джерело/backup перед відновленням і row reconciliation. Зберігати V32/V33/V36 під час майбутньої Spring інтеграції. |
| Live приватні дії | Медіа upload/replace/clear очікує Chrome file-URL permission. Двоакаунтні reply/reports/moderation, двоадресний email change та двоакаунтна доставка очікують контрольованого приймання. Fixtures і read-only UI перевірки вже мають датовані докази. |
| TMDB | 20.11.2026 03:00 UTC refresh успішний; 49/49 linked movies мають original language, поточних refresh errors немає. Для REWIND #36 офіційний анонс [Miraculous](https://miraculous.com/disney-to-premiere-miraculous-world-tokyo-stellar-force/) підтверджує special, але не його TMDB ID; mapping лишається порожнім. |
| Дизайн і продукт | Локальний actor/writer backdrop та writer filmography пройшли live browser acceptance. Production Pages read-only review показав старий bundle: actor без backdrop/executive summary, writer path з `Invalid person link`, CORS/API при цьому працюють. Окрема read-only перевірка Pages показала відсутні CSP, X-Frame-Options, X-Content-Type-Options і Referrer-Policy response headers; CSP і referrer наявні лише як HTML meta policies. У release-копії додано кандидат `frontend/public/_headers`; локальний Wrangler Pages preview повернув усі п’ять policy headers і SPA `GET /`, `GET /uk/home` з 200. Це ще не віддалений `*.pages.dev` preview і не перевіряє Supabase Auth/CORS. Потрібні Cloudflare credentials для ізольованого віддаленого preview, перевірка Auth/CORS allowlists, master sync, CI/Pages publish та post-deploy acceptance; deploy не робився. Same-state Figma parity, токени/типографіка, решта header/footer/layout gaps лишаються відкритими. |
| Free plan | Вбудована leaked-password protection недоступна. Межі capacity та recovery мають увійти до release review. |
