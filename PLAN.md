## Новий пріоритет: GitHub Pages + Supabase Free без інших хостів

Обмеження власника: використовувати лише наявний GitHub і Supabase Free; не додавати платні hosting providers. GitHub Pages публікує повний React застосунок; актуальні deployment і API smoke наведені у checkpoint вище. Публічний Auth acceptance для disposable identity пройшов signup confirmation, recovery/reset і повторний sign-in. 12.11 через залогінену Chrome-вкладку read-only перевірено збережений Site URL, чотири UK/EN login/reset redirect-и та кастомні confirmation/recovery email-шаблони; Dashboard показав Save changes disabled. Gmail SMTP також збережено. Recovery шаблон Dashboard відрізнявся від локального: у репозиторій синхронізовано перевірену логіку вибору мови за `RedirectTo`, без змін live налаштувань. UK/EN token callbacks і видалення disposable identity/outbox ще не прийняті. Локальний MySQL/Compose та старі користувацькі дані не змінювались і не переносились.

1. **Зберегти поточний робочий стан.** Не змінювати локальний Compose MySQL і його volume. Власник окремо дозволив push/deploy GitHub Pages; у release commit включати лише перевірені застосункові файли й потрібну документацію, не додавати сторонні артефакти або локальні secrets. Перед будь-яким перенесенням локальних даних зробити перевірений дамп і зафіксувати обсяг/таблиці.
2. **Перенести базу без хмарних змін спершу — локальний блок виконано.** PostgreSQL baseline лежить окремо у `backend/src/main/resources/db/migration-postgresql`; вона не потрапляє до історичного MySQL Flyway path. Baseline відображає 38 app tables, 55 FK, enum/check constraints, numeric identity IDs, timestamps, indexes, update triggers і початкові site settings; REWIND дані в приватній схемі `rewind`, Auth UUID лишається nullable окремим mapping без email-only linking. MySQL-specific insert/upsert, rating, title filtering, moderation, newsletter timing та outbox шляхи перевірені/розгалужені для PostgreSQL, збережено MySQL defaults. Повний backend suite пройшов **145/145** на PostgreSQL 16.15 і PostgreSQL 17; чистий disposable MySQL 8.4 control suite — **145/145**. Скрипт [`verify-postgresql-rehearsal.ps1`](scripts/verify-postgresql-rehearsal.ps1) створює незалежний dump поза Git, відновлює його у тимчасовий MySQL, імпортує в baseline PostgreSQL, звіряє рядки/IDs/NULL/FK/sequences і запускає ключові API flows. Останній PostgreSQL 17 rehearsal і API-прогін пройшли; точні обсяги наведені в [RELEASE_EVIDENCE](docs/operations/RELEASE_EVIDENCE.md#postgresql-baseline-runtime-and-dump-rehearsal--04112026). Хмарну схему/дані не змінювали.
3. **Перенесення Supabase каталогу завершено; приватна схема підготовлена.** У приватній `rewind` schema імпортовано 50 фільмів, 17 жанрів, 153 жанрові зв’язки, 383 актори, 400 cast links, 52 режисери, 54 director links, 50 зовнішніх рейтингів і 300 зв’язків схожих фільмів. Числові IDs та nullable поля збережені. За дозволом власника додано таблиці `users`, `ratings`, `lists`, `list_items`, `reviews`, `comments`; RLS обмежує записи власником, а роль не може підвищити себе до ADMIN. Live read-only count 09.11.2026: Auth users, REWIND users, ratings, reviews, lists, messages — **0**. Дані старих локальних акаунтів не переносилися.
4. **Hosted Auth та owner bootstrap — частково прийняті live (12.11.2026).** У Dashboard збережено Site URL `https://anton5267.github.io/rewind-letterboxd/`, чотири UK/EN login/reset redirect-и та Gmail SMTP. Власник завершив signup confirmation, password recovery/reset і повторний вхід; read-only звірка підтвердила 2/2 підтверджені Auth identities, 2/2 пов'язані REWIND профілі та 2 активні ADMIN. Залишилися окремі UK/EN callback-перевірки й acceptance видалення disposable акаунта через outbox; звичайний акаунт/дані для цього не видаляти.
   Реєстрація створює лише `USER`, роль не береться з `user_metadata`; старі локальні профілі не зіставляються лише за email. SMTP налаштований у Dashboard, базові confirmation/recovery/reset листи дійшли на disposable alias. Публічний безплатний запуск лишається в межах GitHub Pages + Supabase Free; не переходити на платний план і не створювати VPS/domain залежності.

Auth Site URL, чотири redirect-и, confirmation/recovery шаблони й SMTP прочитані зі збереженими значеннями; локальний recovery template/config/helper відтворюють live вибір UK/EN мови. Confirmation/recovery/reset/sign-in пройдені disposable identity; окремі UK/EN token callback перевірки та безпечний deletion/outbox acceptance цієї identity лишаються відкритими. Admin Movies update/audit/publication-toggle прийняті live із справжньою Admin-сесією; report queue порожня, тому dismissal не тестувався, а curation mutation acceptance ще попереду. 20/49 TMDB-linked фільмів ще без original language, один запис не має підтвердженого TMDB ID; cron активний на 03:00 UTC, усі 49 спроб успішні. Звичайні користувацькі дані не змінювалися; локальна MySQL/Compose база не переносилася й лишається незміненою.

### 4. Перевірки та доставка

Поки триває visual stage, після кожного блока виконувати `npm run verify:build` і ручний огляд Chrome. Автотести не запускати до завершення візуального етапу, як було погоджено раніше.

1. `npm run verify:build`, повний Playwright suite з фактичними skips, backend suite та погоджені security/API/backup/production-config перевірки.

4. Історичний етап доставки commits/push/CI був виконаний до поточної вказівки користувача. Нові локальні зміни не відправляти в GitHub без нової прямої вказівки.
